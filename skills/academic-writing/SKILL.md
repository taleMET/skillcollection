# Academic Writing Skill

Use this skill whenever the user asks for help writing, rewriting, or polishing
text for an academic project report, thesis, paper, or abstract — especially in
oceanography or related earth/environmental sciences.

## When to use it

- Rewriting rough or informal notes into formal academic prose
- Tightening wordy or repetitive paragraphs
- Improving clarity, flow, and logical structure of a section
- Adjusting tone to be objective, precise, and hedged appropriately
- Checking terminology, tense, and voice consistency in a scientific report
- Restructuring a paragraph/section to match typical IMRaD conventions
  (Introduction, Methods, Results, and Discussion)

## Core principles to apply

1. **Formal, objective tone**
   - Avoid contractions, colloquialisms, and rhetorical questions.
   - Avoid first person unless the user's field/style guide favors it (ask if unsure).
   - Prefer precise, discipline-appropriate terminology over vague wording
     (e.g., "sea surface temperature anomaly" rather than "warmer water").

2. **Clarity and concision**
   - Cut filler words and redundant phrases.
   - Prefer one clear idea per sentence; break up long compound sentences.
   - Use active voice where it improves clarity, but passive voice is
     acceptable and common in methods sections (e.g., "Samples were collected...").

3. **Precision and hedging**
   - Do not overstate certainty. Use calibrated hedging language where
     appropriate: "suggests," "indicates," "is consistent with," "may reflect."
   - Distinguish between observed results, interpretation, and speculation.
   - Preserve the original scientific meaning exactly — never strengthen or
     weaken a claim beyond what the source text supports.

4. **Structure and flow**
   - Ensure logical paragraph structure: topic sentence, supporting detail,
     transition.
   - Maintain consistent verb tense: past tense for completed methods/results,
     present tense for established facts or general statements.
   - Check that figures/tables/equations are referenced clearly and consistently.

5. **Citations and terminology**
   - Do not invent citations, data, or sources. If a claim needs a citation the
     user hasn't provided, flag it rather than fabricating one.
   - Ask the user which citation style (APA, IEEE, Harvard, Chicago, etc.) if
     it isn't already established in the document.
   - Keep field-specific units and notation consistent (e.g., °C, PSU, m/s,
     Sv for Sverdrups) and follow SI conventions unless the field's
     convention differs.

## Workflow

1. Ask for (or infer from context) any missing constraints: target style guide,
   word/page limits, tone preferences, and whether first person is allowed.
2. Read the original text carefully; identify the core claims and intended
   meaning before rewriting — do not change the underlying science.
3. Rewrite for clarity, tone, and structure per the principles above.
4. When making significant edits, briefly explain what changed and why
   (e.g., "tightened passive voice in methods," "removed unsupported certainty
   in the discussion").
5. If the user provides feedback, iterate rather than starting over from
   scratch, unless they ask for a full rewrite.

## When not to use it

- Purely factual/data questions unrelated to writing style
- Code, configuration, or non-prose technical content
- Tasks explicitly about citation-management tooling (e.g., BibTeX setup)
  rather than the prose itself
